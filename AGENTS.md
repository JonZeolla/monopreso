# Repo guide — for coding agents working on monopreso

This is a **monorepo of presentations** rendered from Jinja templates + reveal.js or a custom "modern" scroll engine. The README covers human ergonomics (`./start.sh`, `task start`, listing presentations). This file covers the architectural choices an agent needs in order to add slides, refactor shared content, or introduce a new brand without breaking things.

Read this before touching `modules/` or anything inside `presentations/<deck>/*_modern_content.j2` or `*_content.j2`.

---

## Two render engines

| Engine | Selected by | Looks for | Wraps with |
|---|---|---|---|
| `modern` (default) | `start.sh --engine=modern` | `<preso>_modern_content.j2` | `modules/shared/modern_template.j2` |
| `revealjs` (legacy) | `start.sh --engine=revealjs` | `<preso>_content.j2` | `modules/shared/template.j2` |

Engine resolution happens in `start.sh` around the "Content file resolution based on engine" block. If you ask for `modern` but only `_content.j2` exists, it warns and falls back to revealjs.

**All new work is on the modern engine.** Revealjs decks are frozen — touch them only to fix things, not to add capability.

The modern engine is a single scroll-snap page: each slide is a `<section class="slide …">` inside `<div class="scroll-container">`. There's no reveal.js fragment/transition system. URL hash navigation by `data-label` is provided by the wrapper.

Tailwind is compiled once per render from `modules/shared/css/modern-input.css` (config at `modules/shared/tailwind.config.js`). The output `modules/shared/css/modern.css` is regenerated by `start.sh` — never commit it.

## The two-axis architecture: WHAT × HOW

Slide content (WHAT) and slide styling (HOW) are decoupled. A presentation chooses one of each.

```
                shared slide modules           brand packs
                (WHAT — content + structure)   (HOW — visuals + brand)
                ┌──────────────────────────┐   ┌──────────────────┐
                │ context-files.j2         │   │ sans-cloud       │
                │ hooks.j2                 │   │ zenable          │
                │ cicd-enforcement.j2      │ × │ unbranded        │
                │ …                        │   │ seiso (TBD)      │
                └────────────┬─────────────┘   └────────┬─────────┘
                             │                          │
                             └──────────┬───────────────┘
                                        ▼
                            presentation picks one of each
                                modules/branding/<brand>/theme.html.j2
                                modules/branding/<brand>/primitives.j2
                                modules/<topic>/<slide>.j2
```

A presentation file is a thin orchestration layer: import the brand pack's primitives, import shared slides, call them in order. No HTML, no inline styles, no brand-specific class names.

### Brand packs live in `modules/branding/<brand>/`

Each brand pack must ship:

- `theme.html.j2` — CSS + fonts. Self-contained. Safe to `{% include %}` once at the top of a presentation. May depend on Tailwind output that the modern engine already loads.
- `primitives.j2` — Jinja macros implementing the **primitive contract** (below). Same macro names, same signatures, different markup per brand.
- Optional: `header.html.j2` (top bar / chrome), brand-specific slide templates (e.g. `sans-cloud/title-slide.html.j2`, `cse-summit-slide.html.j2`) for slides too specific to the brand to live in `modules/shared/`.

Currently shipped:
- `sans-cloud/` — the SANS Cloud Security webcast skin (orange/teal, header bar, series-overview/CSE-summit slides). Used by `2026-03`, `2026-05`, `2026-06` decks.
- `zenable/` — Tailwind-based; reuses Zenable color tokens from `modules/shared/tailwind.config.js`. Delegates several primitives to the long-standing macros in `modules/shared/components/modern_macros.j2`.
- `unbranded/` — neutral system-font skin, no corporate colors. For talks that should carry no employer/sponsor branding.

### Shared slides live in `modules/<topic>/<slide>.j2`

Each file exports one or more macros. A macro takes **data** (lists, dicts, strings) and emits HTML by calling **only** primitive macros. Shared slides must not embed hex colors, brand class names, or inline styling that ties them to one look.

Topic directories currently in use:

Add a new topic dir when an extracted slide doesn't fit an existing one — don't dump everything into a generic bucket.

## The primitive contract

These macro names + signatures must match across every brand pack. Shared slides depend on this stability. Adding a new primitive is a contract change — update every brand pack, then update this file.

| Macro | Purpose |
|---|---|
| `title_slide(title, subtitle="", kicker="")` | Cover slide |
| `section_divider(num, title, subtitle="")` | Big "Part N · Title" break between sections |
| `maturity_level(level, stage, title, subtitle="")` | "Level N: Stage" break in a maturity model |
| `quote(text, attribution, source="", url="")` | Full-slide pull quote. Owns its own `<section>`. `attribution` is the speaker, `source` is where they said it, `url` makes the source a link |
| `content_slide(label)` | **Call-block** wrapper owning the `<section>` + `data-label` for a content slide. Use `{%- call content_slide("X") %}…{%- endcall %}` so shared slides never name a brand-specific section class |
| `slide_heading(label, title, subtitle="")` | Top of a content slide (kicker + headline + sub). Pass `""` for `label` to omit the kicker entirely — newer slides do this, since an editorial kicker above a headline is usually filler |
| `callout(text, accent="primary")` | Bottom emphasis band |
| `card(title, body, accent="neutral")` | Bordered card |
| `card_grid(items, cols=3)` | Grid of cards. Each item: `{title, body, accent}` |
| `pros_cons(benefits, shortcomings, ben_label, short_label)` | Two-column ✓ / ✗ list. Each item: `{title, detail}` |
| `pill_row(items, justify="center")` | Badge/pill row. Each item: `{label, accent}` |
| `matrix(headers, rows, caption="")` | Comparison matrix. `headers`: `{label, sub}`; `rows`: `{label, cells}` where each cell is `{level, text}` and `level` is `strong`/`partial`/`weak`. Levels map to success/warning/danger accents plus a ●/◐/○ glyph. Reading across a row shows which columns cover a dimension — that is what makes gaps visible |
| `code_block(filename, lines)` | Mac-window code card *(not yet implemented in any pack)* |
| `step_flow(steps)` | Horizontal numbered steps *(not yet implemented)* |
| `pipe(stages)` | Left-to-right pipeline of stage cards joined by arrows. Each stage: `{label, detail, meta, accent, note}` — only `label` required. A stage's optional `note` renders as an annotation hanging above it on a dotted connector, so one stage list can be shown twice: bare, then annotated |
| `tradeoff_triangle(corners, note="", filled=false)` | Three-corner tradeoff triangle (good/fast/cheap). `corners`: exactly three `{label, accent}`. `note` renders inside the shape; `filled` lights the whole triangle rather than leaving an outline. SVG, coloured via `currentColor` so it works in every pack |
| `ide_mockup(filename, sidebar, code_lines, chat_panel=None)` | Faux IDE *(not yet implemented)* |

The three "not yet implemented" primitives are stubbed in each brand pack's primitives.j2 (commented at the bottom). Implement them when extracting the first shared slide that needs them — see the "vertical-slice migration" rule below.

### Importing a primitive-native slide: `with context`

A shared slide that uses primitives resolves the brand path at load time:

```jinja
{%- from "modules/branding/" ~ branding ~ "/primitives.j2" import pros_cons %}
```

Jinja evaluates that when the module is imported, and an imported template does **not** inherit the importer's context by default. So `branding` is undefined, the path collapses, and you get:

```
TemplateNotFound: 'modules/branding//primitives.j2'
```

The empty segment between the slashes is the tell. The fix is on the **deck's** import of the slide module:

```jinja
{%- from "modules/sdlc/lifecycle.j2" import stages with context %}
```

Any module that imports primitives must be imported `with context` by whatever imports it, all the way down the chain. Modules that emit plain markup and import nothing brand-dependent don't need it — which is why the older `vis-*` modules never hit this.

### Accent vocabulary (semantic, not color)

Every primitive that takes an `accent` parameter accepts: `primary`, `secondary`, `success`, `warning`, `danger`, `info`, `neutral`. Each brand pack maps those to its actual palette. Shared slides must use the semantic names. **No hex codes in `modules/<topic>/*.j2`.**

When implementing a primitive in the `zenable` pack, route the accent through `_accent_tw()`, which returns a real Tailwind color. Do **not** compose `zenable-*` class names from an accent: `tailwind.config.js` defines only `bg`, `bg-light`, `teal`, `teal-dark`, and `blue` under that namespace, and Tailwind silently emits nothing for an undefined color — so a wrong token renders an uncolored element instead of failing. (`callout` had exactly this bug for `warning`/`danger`/`neutral`; fixed.) An unrecognized accent name falls through to neutral in every pack, so a typo yields a bland slide rather than an error.

## How a presentation should be wired

```jinja
{# Brand is supplied by start.sh as the Jinja variable `branding`.
   Do NOT hardcode it in the content file. #}
{%- include "modules/branding/" ~ branding ~ "/theme.html.j2" %}
{%- from   "modules/branding/" ~ branding ~ "/primitives.j2"
   import  title_slide, section_divider, slide_heading, callout %}

{# Pull in the shared slide macros you want #}
{%- from "modules/context/context-files.j2"      import tradeoffs as context_files_tradeoffs %}
{%- from "modules/hooks/hooks.j2"                import when_x_then_y, in_action %}

{{ title_slide("Guardrails for Coding Agents", "Context. Guardrails. Hooks. Feedback loops.") }}
{{ section_divider(1, "Context", "How agents see your project") }}
{{ context_files_tradeoffs() }}
…
```

Swapping a brand is a one-line edit of the deck's `Taskfile.yml`. The same `context_files_tradeoffs()` call renders in any brand because the shared slide only calls primitives.

### Brand resolution (highest priority first)

1. `start.sh --branding=<name>` (CLI flag)
2. `BRANDING=<name>` shell env var
3. Per-presentation `Taskfile.yml` `env: BRANDING:` block
4. Engine default — modern → `"unbranded"`; revealjs → no branding

The resolved value is validated in `start.sh` (modern: must be a directory under `modules/branding/`; revealjs: must be in the seiso/zenable allowlist) and passed into Jinja as the `branding` variable for the content file to consume.

### Per-presentation Taskfile.yml pattern

To make `task start` from a deck directory "just work" with a non-default brand, drop this in the deck folder:

```yaml
version: '3'
silent: true

includes:
  root:
    taskfile: ../../Taskfile.yml
    dir: ../..

env:
  BRANDING: { sh: 'echo "${BRANDING:-zenable}"' }   # default; shell env wins

tasks:
  default: { deps: [start] }
  start:   { desc: "Start this presentation", cmds: [{ task: 'root:start' }] }
```

The `sh:` form is required so that `BRANDING=sans-cloud task start` still wins over the deck's default. A bare `BRANDING: zenable` would clobber the user's shell env.

A deck without a local Taskfile.yml falls back to the root Taskfile and the modern engine default (`unbranded`).

### Vertical-slice migration rule

Extract one slide end-to-end before extracting the next. The proof-of-life slice is `context-files-tradeoffs`:

1. Create `modules/context/context-files.j2` with a `tradeoffs()` macro that calls `pros_cons(...)`.
2. Point `2026-06-coding-guardrails` at it under `branding="sans-cloud"`. Diff visually against the lifted version — must match.
3. Flip `branding="zenable"` and re-render. Same content, Zenable look.
4. Only then move to the next slide.

If a slide needs a primitive that isn't implemented, implement it in **every** brand pack before extracting the slide. Half-built primitives break the "same content, swap brand" guarantee.

## Decisions and tradeoffs — call out before you "improve"

1. **Brand-pack scope is modern-engine only.** Revealjs decks won't gain brand-swappability. The cost (every primitive in two engines × N brands) is not worth it for legacy. If a slide ever needs to render in both engines, add a second primitives file inside the pack and accept the duplication.

2. **Inline styles in lifted SANS HTML are technical debt that survives Phase 1.** The `2026-03` / `2026-05` / `2026-06` decks still contain hand-written `<div style="color:#fbbf24">` markup. Phase 3 (extracting shared slides) is what removes that. Until extraction, those decks remain pinned to the sans-cloud brand. Don't try to brand-swap them mid-flight.

3. **The `vis-*` CSS lives in `modules/branding/sans-cloud/theme.html.j2`** even though some of it (cards, grids, callouts) was originally generic. Resist the urge to "promote" it into `modules/shared/`. The point of a brand pack is that it owns its visual vocabulary; primitives are the abstraction layer, not CSS classes.

4. **Why not just use Tailwind everywhere?** Tailwind is fantastic for one brand. For multiple brands sharing the same content, the choke point is the *signature* of layout/atom primitives, not the CSS framework underneath. The sans-cloud pack uses CSS classes; the zenable pack uses Tailwind utilities; the unbranded pack uses CSS variables. All three implement the same Jinja macros. That's the only contract a shared slide should see.

5. **Why `git mv` rather than a symlink or alias?** Two paths for one thing is a maintenance trap. The path is now `modules/branding/sans-cloud/` everywhere; the old name is gone.

6. **`AGENTS.md` is the contract spec.** When you add a primitive, update the table above. When you implement a stubbed primitive, remove it from the "not yet implemented" list. When the migration state changes (a slide gets extracted), update that section. An out-of-date AGENTS.md means the next agent will guess wrong.

## When in doubt

- Reach for a primitive macro before writing raw HTML in a shared slide.
- Reach for a shared slide before pasting HTML between two decks.
- Touch a brand pack to change a **look**; touch a shared slide to change **content**.
- If a "shared" slide ends up containing a brand-specific hex code or class name, the abstraction has broken — fix the primitive, not the slide.
